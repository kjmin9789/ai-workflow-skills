# 태스크 기획문서 작성

## 사용 시점과 목적

“노션 요구사항 작성할게”, “기획문서 정리해줘”, “태스크 요구사항 작성해줘” 요청에 적용한다. 사용자의 기획 요구사항을 개발자가 변경 위치와 완료 조건을 이해할 수 있는 한국어 Markdown 문서로 정리한다.

## 저장 방식

- 저장 위치: 사용자 또는 프로젝트 지침에서 지정한 문서 작업 폴더 아래 `request/YYMMDD-태스크명.md`. 별도 지정이 없으면 현재 프로젝트 폴더를 기준으로 한다. 스킬 설치 폴더에는 결과물을 저장하지 않는다. 모든 태스크 문서는 공통 `request` 폴더에 저장하며 태스크별 폴더는 만들지 않는다.
- 날짜는 사용자가 지정한 날짜를 우선한다. 날짜 지정이 없으면 한국 시간 기준 작성일을 사용한다.
- 파일명에는 태스크명을 읽기 쉬운 한국어로 사용하고 공백을 유지한다. 경로 구분자인 `/` 등은 하이픈으로 바꾼다.
- 기존 태스크 수정은 같은 파일에 반영한다. 다른 태스크와 파일명이 겹치면 덮어쓰지 말고 구분되는 이름을 사용한다.
- 완성 후 파일 링크를 전달한다. Notion 직접 등록·수정은 별도 명시적 요청이 있을 때만 수행한다.
- 문서 작성 요청만으로 실제 제품을 구현하거나 새 에이전트 채팅을 생성하지 않는다.

## 작성 원칙

- 제목은 `[적용 플랫폼] 변경 내용`으로 쓴다. 플랫폼이 지정되지 않았다면 임의로 붙이지 않는다.
- `개요`, `적용 범위`, `요구사항`, `완료 기준` 소제목을 사용한다. 요구사항은 변경 항목별 번호가 있는 하위 소제목으로 나눈다.
- 제공된 화면 표시와 주석은 요구사항의 근거로 사용하되, 최종 문서에서는 “주석 1”, “두 번째 주석” 같은 표현을 제거하고 실제 기능·영역 이름으로 설명한다.
- 참고 화면 URL 항목은 기본적으로 넣지 않는다. 사용자가 명시적으로 요구한 링크는 포함한다.
- selector가 제공되면 해당 요구사항 바로 아래에 `대상 영역 selector` 또는 구체적인 버튼 이름을 붙이고 `css` 코드 블록에 원문 그대로 넣는다. 확인하지 않은 selector를 만들지 않는다.
- selector가 변경 전 화면 기준이고 요소 추가로 순서가 달라질 수 있으면 짧게 명시한다.
- 변경 위치, 배치 순서, 변경 전후 수치, 적용 범위를 구체적으로 적는다. 아이콘 그래픽 크기와 버튼·터치 영역의 너비 및 높이를 구분한다.
- 브레이크포인트별 규격은 표로 정리한다. Fill이 적용되는 영역과 실제 터치 범위를 명확히 적는다. 클릭커블 표현 효과와 클릭·터치 기능을 혼동하지 않는다.
- 특정 태스크에서 사용한 수치를 다른 태스크의 기본값으로 사용하지 않는다.
- 사용자가 제공하지 않은 동작·수치·담당자·일정·구현 방법을 임의로 확정하지 않는다. 결과를 바꾸는 핵심 정보가 빠졌으면 짧게 질문하고, 나머지는 먼저 정리한다.
- 완료 기준은 요구사항을 확인할 수 있는 체크박스로 작성한다. 요청하지 않은 기능이나 별도 작업을 추가하지 않는다.
- 후속 수정 시 제목·개요·요구사항·완료 기준을 함께 갱신해 서로 모순되지 않도록 한다.

## 기본 양식

```markdown
# [플랫폼] 태스크명

## 개요

변경 목적과 결과를 간결하게 설명한다.

## 적용 범위

- **플랫폼:** 적용 플랫폼
- **위치:** 변경 화면과 영역

## 요구사항

### 1. 변경 항목

- 변경 위치와 원하는 동작을 설명한다.
- 필요한 규격과 배치 조건을 적는다.

### 2. 변경 항목

- 다음 변경 사항을 설명한다.

## 완료 기준

- [ ] 첫 번째 요구사항의 완료 조건
- [ ] 두 번째 요구사항의 완료 조건
```

위 양식의 예시 문구는 실제 요구사항으로 바꾼다. 항목 수는 요청에 맞추고, selector가 있으면 관련 요구사항 아래에 코드 블록을 추가한다.

## 저장 예시

사용자가 날짜를 `260915`, 태스크명을 `차트 도구 터치 영역 확대`로 지정하면 `request/260915-차트 도구 터치 영역 확대.md`로 저장한다.
